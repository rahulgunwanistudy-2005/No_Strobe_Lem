# HazardTrack 1.0 — contract draft

A HazardTrack describes one SDR video under one viewing profile. `.hzt.json` is canonical. The committed JSON Schema is generated from `nostrobe.domain.models.HazardTrack`; regenerate with `cd engine && uv run nostrobe schema`. Times are seconds on the media timeline. `generated_at` is an aware UTC timestamp. Unknown fields are ignored; unknown format versions are refused.

The root object contains `format="hazardtrack"`, `format_version="1.0"`, `profile`, `media`, `events`, `veils`, `verifier`, `generated_at`, and `stats`. Profiles are `broadcast`, `local`, and `kids`. See `schema/hazardtrack.schema.json` for property constraints and `examples/contract.hzt.json` for a **fabricated contract fixture**, not an analyzed or playable asset.

Event kinds are `luma_flash`, `red_flash`, and `extended_flashing`. Severities are `fail` and `warn`. `VeilCue.covers` references event ids; alpha and display-code gray lie in [0,1]. Full-strength veil begins at `t_on`, holds through `t_off`, with ramps before/after those bounds. Negative veil times near media start are allowed and must be clipped by the player. Shared minimum ramp duration is 0.5 s.

Readers must refuse `verifier.passes=false`. Publishing must also reject residual events and require full verification against the matching video and parameter hash. Schema validation alone cannot establish that a video was analyzed or that mitigation works.

WebVTT serialization begins in S3: `WEBVTT`, a `NOTE hazardtrack` metadata block excluding events/veils, and JSON VeilCue payloads spanning `[t_on-ramp_in_s,t_off+ramp_out_s]`. No WebVTT reader/writer or HTML5 reference player is implemented in S1.

TypeScript is generated by `npm run types:generate`; `npm run types:check` detects drift. It lives in `spec/generated/` until TV creation in S5. Runtime JSON validation is separate from TypeScript types.

## Playback semantics

For each cue, evaluate `alpha * max(0, min(1,
(t - t_on + ramp_in_s) / ramp_in_s,
(t_off + ramp_out_s - t) / ramp_out_s))`. Opacity is zero before the
ramp-in support, reaches the target at `t_on`, holds through `t_off`, and
returns continuously to zero at `t_off + ramp_out_s`. Seek directly to this
value; pause holds it. A seek into the full-strength plateau snaps to target.
Players clip playback to `[0, media.duration_s]`; they do not compress ramps
that began before media time zero. If external tracks overlap cues, choose
the greatest current opacity; ties choose lower gray, then lexical cue id.
Apply a single uniform overlay, never stack overlapping overlays.

A positive verification offset means the veil is late: evaluate the timeline
at `media_time - offset`. Source Y codes are normalized as `code8 / 255`,
RGB channels as `channel8 / 255`; both blend toward the same normalized
code gray. Y returns to 10-bit table coordinates using `*255*4` without
quantizing the simulated output. RGB uses inverse BT.709 before averaging.
This is the specified simulation model; actual device fit is an S5 gate.

Event padding defines the full-opacity plateau (lead/tail). Ramp supports
add `min_ramp_s` outside this plateau. Plateaus clip to the media timeline;
ramps may start before zero or finish after duration. Segments merge when
padded plateaus are separated by at most `merge_gap_s`, and also when ramp
supports would overlap. No opacity occurs outside these merged padded
supports. This resolves the brief's ambiguous 'outside padded segments'
wording while preserving its explicitly required lead/tail and ramps.

## WebVTT encoding

`WEBVTT` is followed by a `NOTE hazardtrack` block containing one JSON line
with metadata excluding events/veils. A separate `NOTE hazardtrack-events`
block preserves event provenance as a JSON array. Each cue has an id,
`HH:MM:SS.mmm --> HH:MM:SS.mmm`, and the exact VeilCue JSON on one line.
Cue starts clip to zero; times round to nearest millisecond, with carry.
Payload floats remain exact and are authoritative for playback. Cues sort
by support start, then id. Overlaps are valid. The reference parser checks
header, timing, ordering, payload bounds, references and verification.
Additional unknown NOTE blocks are ignored. See `examples/web/` for the
portable video-overlay reader.

## Optional 1.0 extensions

`stats.mean_delta_cd_m2` reports duration-weighted mean absolute luminance
change over the union of active veil supports, including ramps (zero when
unveiled). `stats.mean_alpha` uses the same active-runtime denominator.
`unresolved_segments` lists `{start,end,covers,reason}`. These extensions
have empty/zero defaults for older fixtures. Any unresolved segment forces
`verifier.passes=false`, even if a conservative local check failed but the
final detector found no residual failures. Such artifacts are debugging-only
`*.unresolved.hzt.json`; no WebVTT is published. Source events remain intact
when a final verification retry expands coverage from residual evidence.
